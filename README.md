# RJAB Attendance Camera (Fork of RJAB Camera)

This repository is the attendance-specific fork of the existing RJAB Camera Module. The original Telegram camera repository is kept unchanged.

## What is retained

- Live front-camera capture (no gallery picker)
- MediaPipe face detection / capture guidance and existing image-quality checks
- GPS capture with high-accuracy request and accuracy metadata
- Reverse address lookup using the existing OpenStreetMap Nominatim endpoint
- RJAB watermark generation
- Mobile-responsive camera interface

## What is changed

- Removed Telegram Mini App SDK dependency and auto-close flow
- Removed Telegram ID, Telegram session, and hard-coded legacy Apps Script upload endpoint
- Requires a launch ticket and a parent portal window/frame
- Returns the captured selfie and GPS metadata to the authenticated Employee Portal using `window.postMessage`
- Waits for an explicit server-side acknowledgement from the portal before showing success
- Watermark wording now says `ATTENDANCE VERIFICATION` and `CAPTURED USING RJAB ATTENDANCE CAMERA` (the camera alone does not claim that backend biometric verification has passed)

## Camera URL launch contract

The Employee Portal must launch this page over HTTPS with these query parameters:

- `ticket`: opaque, random, short-lived, one-time ticket generated by the Apps Script backend
- `mode`: `TIMEIN` or `TIMEOUT` (display hint only; the server must derive the authoritative action from the ticket)
- `parentOrigin`: exact HTTPS origin of the portal window that opened this camera

Example only (replace the domain and ticket with real values):

```text
https://YOUR_GITHUB_USERNAME.github.io/rjab-attendance-camera/?ticket=OPAQUE_ONE_TIME_TICKET&mode=TIMEIN&parentOrigin=https%3A%2F%2Fscript.google.com
```

The camera removes the query string from the visible URL immediately. The ticket is kept in page memory only. Do not put employee IDs, names, passwords, session tokens, or other personal data in the URL.

## Message sent to the parent portal

After the employee captures a live photo, the camera obtains GPS coordinates, GPS accuracy, GPS timestamp, readable address, and applies the watermark. It then sends:

```javascript
{
  type: "RJAB_ATTENDANCE_CAPTURE",
  version: 1,
  ticket: "OPAQUE_ONE_TIME_TICKET",
  payload: {
    action: "TIME_IN", // or TIME_OUT; informational only, verify against ticket
    photoDataUrl: "data:image/jpeg;base64,...",
    photoMimeType: "image/jpeg",
    latitude: "...",
    longitude: "...",
    gpsAccuracyMeters: 18,
    gpsTimestamp: "...",
    address: "...",
    clientCapturedAt: "...",
    cameraQuality: "PASSED",
    cameraVersion: "attendance-camera-1.0.0"
  }
}
```

## Required parent-side acknowledgement

The portal must listen for messages from the exact deployed camera origin and validate all of the following before saving anything:

1. `event.origin` is exactly the camera GitHub Pages origin.
2. `event.source` is the exact popup or iframe it opened.
3. `event.data.type` is `RJAB_ATTENDANCE_CAPTURE`.
4. The ticket exists, has not expired, has not been used, and is bound server-side to the currently authenticated employee and intended attendance action.
5. The server validates the action and attendance state; do not trust the `mode` query string or `payload.action`.
6. The server records its own timestamp. `clientCapturedAt` and `gpsTimestamp` are supporting evidence only, not authoritative attendance timestamps.
7. The server validates latitude/longitude ranges, accuracy threshold, photo size/type, and duplicate submission rules.
8. The server stores the image in Drive and attendance data in Sheets only after successful validation.

After the Apps Script backend has successfully processed the capture, the portal must reply to the same camera window:

```javascript
cameraWindow.postMessage({
  type: "RJAB_ATTENDANCE_CAPTURE_ACK",
  ticket: message.ticket,
  ok: true,
  message: "Attendance capture received."
}, event.origin);
```

For a rejected submission, send `ok: false` and a safe user-facing `message`. Do not include secrets, stack traces, API keys, or internal tokens in the reply.

## Important integration boundary

This ZIP is the **camera front-end fork only**. It does not include or modify the main Google Apps Script Attendance Portal, the Cloudflare Worker, ticket issuance/consumption functions, employee authentication, attendance database logic, or the EdgeFace/MiniFASNet biometric matching service. Those must be connected in the main project. The MediaPipe checks in this camera module are capture/quality guidance; they are not a substitute for the separate registered-face match and liveness verification flow.

## Deployment

1. Create a new repository named `rjab-attendance-camera`.
2. Upload the contents of this folder to the repository root.
3. Enable GitHub Pages for the desired branch/root.
4. Use the published HTTPS URL from the Employee Portal.
5. Set the exact published camera origin in the portal's message validation.

## Test status

The source was statically checked for JavaScript syntax and legacy Telegram/GAS endpoint references. End-to-end operation still requires the portal-side ticket and acknowledgement handlers described above. Test on the actual iPhone/Android browsers before production.
